Change logs

v0.11 2026-07-13 06H

  • Restored the recurring-adder feature (buildRecurringAdder, openNewRecurringItemEditor) and the findIn/trashItem/editItem/editNote listKey-optional refactor from the crazierers branch, keeping only the RECURRENCE_KINDS declaration-order fix (moved above load() so validateRecurrence() no longer throws on stored recurrence data).
  • Fixed the Completed and Recurring views (derived filters over itemsById) still showing items after they'd been deleted - they now check findInTrash() too, not just isDone/recurrence.
  • Fixed recoverItem pushing unlinked completed/recurring items into List 3 on recover instead of restoring them unlinked, the way they were before being trashed.
  • Known bug: editing a note in List 0 is currently broken - not yet investigated.

v0.10 2026-07-12 14H

  • Checkpoint C: added the Basics zone (list -1) to the Today card, above zone 0. Check/delete work on it like any other list; it deliberately sits outside the swipe/hamburger move chain since it isn't part of the 0-1-2-3-3.5-4 urgency progression, and it has no adder yet since it'll be populated by Recurring items via rollover (Checkpoint E) instead of typed in by hand.
  • Deleted all "Select to keep" code (state, row rendering, header buttons, CSS) instead of just leaving it hidden/unhooked.

v0.9 2026-07-12 12H

  • Reworked checkpoint B of the item/list data model: completing an item moves it to today's zone 0 unless it's already sitting in zone -1 or 0; unchecking always sends it to List 2, regardless of where it currently is. Items no longer carry an origin field.
  • Completed is now a derived filter (isDone and not recurring) instead of its own stored list, matching how the Recurring view will work once that lands.
  • Fixed a few things this uncovered along the way: a done item sitting in zone 0 now renders correctly checked instead of always showing unchecked, the randomizer no longer offers already-completed items as candidates, and the Completed view's menu no longer offers Move up/down.

v0.8 2026-07-10 19H

  • Checkpoint B of the item/list data model rewrite: items now carry isDone, lastDone, and origin fields.
  • Completing an item records which list it came from (origin) and when (lastDone); unchecking it from Completed now sends it back to that exact list instead of always dumping it into List 2.

v0.7 2026-07-10 07H

  • Checkpoint A of the item/list data model rewrite: items are now stored once each in a single itemsById table, and every list (Today's zones, Lists 2/3/3.5/4, Completed, Trash) just holds ids into it instead of full copies of the item.
  • Pure refactor, no visible behaviour change yet — this is prep for linking one item into multiple lists at once (recurring items, Basics, retroactive past-day logging) in upcoming checkpoints.
